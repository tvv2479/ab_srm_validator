# SRM Validator: Проверка соотношения выборок в A/B эксперименте

## О проекте

Проект посвящён обнаружению **Sample Ratio Mismatch (SRM)** — критической проблемы в A/B тестировании, при которой фактическое соотношение групп отличается от запланированного. SRM делает результаты эксперимента смещёнными и ненадёжными, поэтому его необходимо выявлять до анализа целевых метрик.

В ноутбуке [`srm_validator.ipynb`](srm_validator.ipynb) реализована **трёхуровневая проверка SRM** на данных реального эксперимента:

1. **Критерий хи-квадрат Пирсона** — отраслевой стандарт (используется Optimizely, GrowthBook и др.).
2. **Z-тест на одну пропорцию** — даёт направление перекоса (какая группа недобрала/перебрала).
3. **Последовательный тест SSRM (Optimizely)** — позволяет обнаружить SRM на ранней стадии, отслеживая p-value по мере накопления трафика.

## Данные

Использован файл `exp1.csv` (~4.16 млн строк, 3 столбца):

| Поле      | Описание                                      |
|-----------|-----------------------------------------------|
| `user_id` | Идентификатор пользователя + буква группы (A/B) |
| `date`    | Дата и время события                          |
| `url`     | URL посещённой страницы                       |

**Целевое событие** (`event_flag`) — посещение определённых страниц (директории, профили владельцев, контакты).  
**Группы** кодируются последней буквой `user_id`: `A` или `B`.  
**Плановое соотношение**: 50% / 50%.

## Методология

1. **Подготовка данных**:
   - Очистка `user_id` от буквы группы.
   - Извлечение группы (`A`/`B`).
   - Разметка целевого события по регулярному выражению.
   - Сортировка по дате.

2. **Проверка SRM**:
   - Анализ проводится на **уникальных пользователях** (71 005), а не на всех строках, чтобы избежать искусственного завышения размера выборки (один пользователь может генерировать до 999 событий).
   - **Хи-квадрат**: сравнение наблюдаемых и ожидаемых частот.
   - **Z-тест**: проверка гипотезы \(H_0: p_A = 0.5\), определение направления перекоса.
   - **SSRM**: последовательный тест, фиксирующий момент, когда p-value опускается ниже 0.05.

3. **Обоснование выбора тестов**:
   - Наблюдения независимы (пересечений между группами нет).
   - Данные категориальные, соотношение фиксировано.
   - Совместное использование трёх методов даёт устойчивый вывод и исключает ошибку реализации.

## Результаты

| Показатель               | Значение                     |
|--------------------------|------------------------------|
| Уникальных пользователей | 71 005                       |
| Группа A                 | 38 341 (54.0%)               |
| Группа B                 | 32 664 (46.0%)               |
| Ожидаемое соотношение    | 50% / 50%                    |
| Хи-квадрат (p-value)     | \(1.03 \times 10^{-100}\)    |
| Z-статистика             | 21.37                        |
| Z-тест (p-value)         | \(2.38 \times 10^{-101}\)    |
| SSRM обнаружил SRM после | 3 430 пользователей (4.8% трафика) |

**Вывод**: все три метода единогласно подтверждают наличие SRM. Перекос не случаен, сплит-система работает некорректно. Результатам эксперимента доверять нельзя.

## Рекомендации

1. **Не принимать продуктовые решения** на основе данного эксперимента.
2. **Провести аудит системы сплитования**:
   - Проверить алгоритм хеширования и распределения по бакетам.
   - Проверить логирование (не теряются ли события группы B).
   - Проверить ETL-фильтры (не отсекаются ли пользователи группы B чаще).
3. **Перезапустить эксперимент** после устранения причины.
4. При наличии лога назначения групп — запросить его для локализации ошибки.
